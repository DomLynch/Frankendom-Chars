# GPT web handover — 30 points

Repository: https://github.com/DomLynch/Frankendom-Chars

Copy these instructions into the assistant that will do the work. They describe the project; they do not grant tools or credentials that the session does not have.

1. Work only on Frankendom character design, reconstruction, fitting and review; exclude the game.
2. Start with README.md, PROJECT_STATE.md, the chosen character page and skills/frankendom-character-pilot/SKILL.md.
3. The catalog contains Witch, Nightborn, Knight, Dwarf and Plague Doctor, each L2–L10.
4. Download the chosen character's release archive; Witch has separate review and source archives.
5. Verify archive and model SHA256 values in catalog.json before modifying anything.
6. Confirm actual file execution, image inspection and authenticated Hugging Face access; never claim a job ran without a receipt.
7. Keep tokens in secret storage or authenticated SDK login, never in chat, scripts, commits or screenshots.
8. Preserve original character inputs and work on a separate candidate copy.
9. Preserve identity, body proportions, posture, weapon and the approved face/coverage decision.
10. Preserve skeleton hierarchy, inverse binds, original weights where retained, and exact animation timing/data.
11. Use grounded, gritty medieval-fantasy surfaces and readable silhouettes rather than oversized bodies.
12. Preserve L1 originals; L2 brown leather, L3 bone/hide, L4 copper and L5 bronze.
13. Continue L6 iron, L7 steel, L8 blackened steel/ruby, L9 emerald and L10 full gold.
14. Give L8–L10 different headgear geometry; recolouring one helmet is insufficient.
15. Honour each character's closed-helmet and arm/hand/thigh/leg/foot coverage requirements.
16. Prove one pilot per materially different assembly method; a closed helmet does not validate an exposed-face hood.
17. Keep reference artwork separate from actual exported-model evidence.
18. Use saved TRELLIS donors for fitting repairs; do not regenerate to fix weights, transport or missing assembly work.
19. For genuinely new donors, begin at 1024 reconstruction, 100k target triangles and 2048 textures; increase only for demonstrated detail needs.
20. Record the service revision, licence, seed, actual settings, dependencies, transforms and input/output hashes.
21. Distinguish shared TRELLIS GPU inference from bounded cloud Blender CPU fitting/rendering; consult docs/CLOUD_WORKFLOW.md.
22. Verify a write/read round trip using the actual job credential; login or successful submission alone is insufficient.
23. Set an explicit timeout and spending bound; persist models before rendering and group uploads without reusing mutable temporary files.
24. Fit surfaces in Blender while preserving useful topology and UVs; derive anatomy in the correct bind coordinate frame.
25. For retained faces, remove donor facial remnants and unwanted original hood surfaces; inspect front, close-up, side and rear.
26. Validate every visible skinned primitive, including reused source pieces and linings; retained geometry can still fail in the new assembly.
27. Reimport the final GLB and check front/back/side, head, attack/guard/kick, 375px views and a measured fight-scale figure.
28. Compare exact animations and Khronos error details with the original; report inherited errors rather than hiding them or claiming zero errors.
29. Deliver models, donors, scenes, ordered repairs, hashes, render receipts, coverage matrix and explicit remaining defects; earlier scenes may predate repairs.
30. Report completion precisely: Witch L10 is a finished separate asset, several other ranks still need cleanup, and game/slot/finisher/phone acceptance is not established.

Suggested first assignment: “Using this handover, inspect one selected character and propose the smallest repair or new rank pilot. Preserve its original rig and approved direction. Reuse saved donors. Show actual exported-model proof before batching.”
